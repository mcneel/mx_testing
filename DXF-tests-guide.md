# DXF import and export tests — how they work, and how to add one

**Scope:** the DXF tests in the `FileIO` project. Implementation lives in
`FileIO\DXF\DxfImportBase.cs` and `FileIO\DXF\DxfExportBase.cs`; the folder-to-fixture mapping is
in `FileIO\Rhino.Testing.Configs.xml`.

The DXF suites are the STEP/IGES pattern applied to a third format. Everything the
`STEP-tests-guide.md` says about the shared machinery holds unchanged (sidecar oracles,
present-keys-only assertion, `#`/`!`/`bak` conventions, `[Explicit]` Regenerate, future/large
tiers, `Optional` private_models locations), on the `MX_DXF_*` / `MX_DXFEXPORT_*` namespaces with
`MX_DXF_RELTOL`/`MX_DXF_ABSTOL` comparison slack. Fixtures: `DxfImport` / `DxfExport` (default
run) + `DxfImportFuture` / `DxfImportLarge` / `DxfExportFuture` / `DxfExportLarge` (`[Explicit]`),
folders `models\DXFfile*`, extension `.dxf` (+ `.3dm` in export folders). This file covers only
what is DXF-specific.

## DXF-specific behaviour worth knowing

**DXF has no RhinoCommon class of its own — `FileDwg` covers it.** The ACAD plugin registers
`.dwg` and `.dxf` and dispatches on the path's extension, so `FileDwg.Write(*.dxf, …)` writes
ASCII DXF and `FileDwg.Read` reads it. The suite uses `FileDwg.Read`/`FileDwg.Write` with full
explicit options on BOTH sides, never bare `RhinoDoc.Import`/`Export`:

- the import plugin ignores option dictionaries with fewer than two entries (a clipboard-paste
  special case), so partial hand-built dictionaries are silently dropped — always pass a full
  `FileDwgReadOptions`;
- a bare headless `doc.Export("x.dxf")` runs on the NATIVE defaults (ACAD 2007 / AC1021), while
  `FileDwg.Write` with default options writes 2018 / AC1032 — the suite standardizes on the
  latter and asserts `$ACADVER` structurally in every run.

**The write options genuinely plumb** (unlike IGES): the export dictionary drives the native
writer, so option-varied corpus models are meaningful — `solids-acis.dxf` is written with
`surfacetype solids` and demonstrably produces ACIS 3DSOLID entities that re-import closed.
**Three known defects (RH-98711)**, all silent, all pinned in sidecars as requests until fixed:

| Key | Defect |
| --- | --- |
| `simplifytolerance` | managed writes a Double, native reads it with TryGetBool — never applies |
| `curveusemaxangle` | managed writes a Bool, native reads it with TryGetDouble — never applies |
| `meshtype 3dface` | managed serializes "ThreeDFace", native matches only "ThreeDFaces" — falls through to lines |

The committed corpus never pins `3dface` (a model named for it would lie); the two dead keys are
pinned in every baseline so the day the type mismatches are fixed, baselines diff loudly.

**Import quirks the baselines record:** paper space is skipped in import mode (only model-space
entities count); and the `ModelUnits`/`LayoutUnits` read options do NOT rescale geometry headless
(the unit scale factor is only computed inside the options UI) — coordinates arrive as the raw
numbers in the file. Deterministic, but a real gap; if it is ever fixed, every pinned bbox/area
shifts and the diff will say so.

**The structural checks** (the no-baseline floor, counterpart of STEP's Part 21 and IGES's
S/G/D/P/T checks) come from the ASCII DXF grammar:

- the file is an even sequence of group-code/value line pairs, every code an integer;
- exactly one `0/EOF` pair, at the end;
- `SECTION`/`ENDSEC` balance, never nested, each `SECTION` named by an immediate `2/<name>` pair;
- `HEADER`, `TABLES`, `BLOCKS`, `ENTITIES` present and in that order;
- `$ACADVER` matches the sidecar's pinned `acadversion`;
- `$INSUNITS` is 4 (millimeters) for a millimetre source (2000+ files);
- the ENTITIES section is non-empty.

## The corpus

Generated by `FileIO\DXF\AuthorDxfCorpus.cs` (same policy and re-authoring flow as IGES —
`MX_DXF_AUTHOR_OUT_DIR=models`, then `MX_DXF_REGEN=*` / `MX_DXFEXPORT_REGEN=*`, then READ every
sidecar before committing). Seven models covering 2D entities, splines/ellipses, ACIS solids,
polyface meshes (DXF's meshes survive — the anti-IGES), nested + unreferenced blocks (DXF
preserves assembly structure), nested layers/colors, and TEXT/dimension/hatch; plus
`!empty-entities.dxf`, a hand-written structurally-valid file with an empty ENTITIES section that
is expected to fail (its baseline states the deliberately-unreachable wanted state — regeneration
skips `!` models in every suite).

`models\DXFfile-export\rhino-native-mix-dxf.3dm` is the export source. Its baseline's two columns
read as the writer's default loss profile: under `surfacetype curves` every brep and extrusion
collapses to wireframe (the only surviving area/volume is the mesh's), meshes and blocks survive,
text and dimensions survive as `other`.

```bash
MSBuildEnableWorkloadResolver=false dotnet test FileIO/FileIO.csproj -f net48 --no-build --filter "FullyQualifiedName~FileIO.DxfImport"

```
