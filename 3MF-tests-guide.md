# 3MF import and export tests - how they work, and how to add one

**Scope:** the 3MF tests in the `FileIO` project (`FileIO\ThreeMF\`). Seventh format on the
shared pattern: fixtures `TmfImport`/`TmfExport` (+ `[Explicit]` `-future`/`-large`), folders
`models\3MFfile*`, extension `.3mf`, namespaces `MX_TMF_*` / `MX_TMFEXPORT_*`.

## 3MF-specific behaviour worth knowing

**Export has an API, import does not.** `File3mf` is write-only - there is no `File3mf.Read` in
RhinoCommon - so the import side goes through `RhinoDoc.Import`, which forces import and batch
mode and takes no options. Nothing about the read is pinnable, which is worth remembering when a
baseline moves: only the writer's behaviour is under this suite's control.

**Only one write option changes geometry.** `File3mfWriteOptions` is mostly package metadata
(title, designer, copyright); the exception is `MoveOutputToPositiveXYZOctant`, which exists
because 3MF requires non-negative coordinates. It is the one option the sidecar pins, and
`tmf-negative-octant.3mf` - a sphere authored at negative coordinates - is the model that
exercises it. Its baseline bbox records where the geometry landed.

**The structural checks read the package as what it is: an OPC ZIP.** Rather than scanning bytes
for magic numbers, the checker opens the archive and walks the parts a valid 3MF must have:

- the ZIP local-header magic and a findable end-of-central-directory (a truncated package fails
  here, since the directory lives at the end);
- `[Content_Types].xml`, without which it is not an OPC package at all;
- `_rels/.rels`, which must parse as XML and declare a relationship to a `.model` part;
- that part must actually exist in the archive - a dangling relationship is a broken package;
- the model part must parse as XML, have `model` as its root element, and declare a `unit`
  attribute that is one of the six the 3MF specification allows.

That last one matters more for 3MF than for most formats: the file carries its own unit, so a
wrong unit silently rescales the part on a 3D printer.

## The corpus

Generated by `FileIO\ThreeMF\AuthorTmfCorpus.cs`: a closed mesh box, two disjoint bodies (3MF
keeps them as separate objects, unlike STL where they collapse into one triangle soup), a brep
and an extrusion that the writer must mesh on the way out, a coloured pair on named layers, and
the negative-octant sphere.

## Running

```bash
MSBuildEnableWorkloadResolver=false dotnet test FileIO/FileIO.csproj -f net48 --no-build --filter "FullyQualifiedName~FileIO.TmfImport"
MSBuildEnableWorkloadResolver=false dotnet test FileIO/FileIO.csproj -f net48 --no-build --filter "FullyQualifiedName~FileIO.TmfExport"
```
